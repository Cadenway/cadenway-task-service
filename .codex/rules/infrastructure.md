# Infrastructure layer

- Use the [V2 module layout](../skills/cw-hexagonal-module-layout/SKILL.md) for persistence and adapters. Bind their ports in composition.
- Repositories implement the ports declared by the application layer; they map rows to domain
  objects and back, nothing more.
- Use the ORM already declared in package.json; never add a second one.
- Scope queries by `organization_id` from the verified context. Apply the same scope to related
  records loaded for the result.
- For collections, cap the page size and use the contract order with a stable tie-breaker where
  values can tie. For example, load assignees for the task IDs on the page in one batch so the
  number of queries stays bounded as the page fills.
- Back query patterns with indexes. Inspect the query plan with representative data before
  adding an index. Verify that it supports the filters and ordering the route actually uses.
- External clients (payment, email, Git providers, storage) sit behind a port with a fake for tests.
- The ORM is Drizzle (`drizzle-orm` over `pg`); migrations are generated by `drizzle-kit` from the
  `*.schema.ts` files of this layer.
- Naming, common columns, row-level security, enumerations, pool size and timeouts follow the
  `cw-database-conventions` skill: load it before writing a schema or a query.
